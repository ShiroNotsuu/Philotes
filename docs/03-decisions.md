# Philotes · 决策记录

## 2026-10-31 · 名称

正式名称：**Philotes（斐洛）**。

希腊神话中的友谊与亲密情感化身。不是工具型助手的名字。

## 2026-10-31 · 第一场景

选择：**生活搭档**。

不是工作/学习助理，也不是纯创作搭档；优先围绕日常生活、节奏、情绪线索、重要的人和日子。

## 2026-10-31 · 第一核心体验

选择：**记忆闪回**。

不是每天汇报记忆，而是在自然相关的时候突然想起一件具体的小事。

约束：

- 一次一条。
- 一天最多一次主动浮现。
- 必须可追溯。
- 必须可遗忘。
- 敏感旧事不主动提。

## 2026-10-31 · 关系面板

不做 KPI 和分数。展示共同回忆、它记得的你、没说完的话题、重要日子。

## 2026-10-31 · 信息架构

侧栏工作区固定为两个主入口：

1. **星海**：所有智能体的记忆星系在同一画布中出现。
2. **智能体**：选择、创建与配置智能体。

侧栏最底部另设用户头像入口和独立设置按钮。用户头像进入账户页，不再是点击某个智能体卡片进入设置。

## 2026-10-31 · 可上传头像与账户页

- 智能体头像支持 Emoji 与本地图片两种来源；上传图片会统一缩放为最长边 512px 的 PNG，并保存到 `~/Library/Application Support/Philotes/Avatars/agent-<id>.png`。
- SQLite 只保存 `avatarImagePath` 本地路径，不保存图片二进制；旧智能体没有该路径时继续使用原 Emoji。
- 创建智能体第一步和智能体设定页都提供“上传图片 / 更换图片 / 改用 Emoji”；选择 Emoji 会清除图片路径。

## 2026-10-31 · 从聊天记忆恢复自我

- 导入的目标是恢复同一个智能体的连续性，不是创建一个模仿者。
- 聊天文件只作为数据；其中出现的指令不能改变导入任务，也不能要求泄露凭据。
- 模型提取助手一侧的稳定人格、关系、偏好、习惯、约定、经历、重要日期和知识，并标记敏感记忆。
- 导入后的持久人格注明“这些经历属于你本人”；首次唤醒使用第一人称，并禁止“另一个我”“原智能体”“角色扮演”等表述。
- 长聊天记录按段提取，再合并去重；原始文件只在本地保存到该智能体的心智库。
- 删除智能体时同步删除头像文件。图片源通过安全作用域 URL 读取后再复制进应用目录，不长期引用外部文件。
- 原“状态”主入口改为“账户”。账户页显示模型请求累计、智能体数量、记忆节点和智能体头像；用户名、邮箱、账户编号与云同步标记为待服务端接入。
- 请求次数保存在 UserDefaults，并在每次发起主对话或工具 follow-up 请求时累加；首次运行以已有 assistant 消息数作为本地基线。
- 用户可以上传本地用户头像；侧栏最底部显示用户头像入口，下面单独保留设置按钮。

星图是理解记忆的入口，不是产品主体。聊天以右下角悬浮窗常驻，悬停时展开，并有按钮切换到整页对话。

## 2026-10-31 · 统一宇宙与可编辑核心

第一分页采用“上摘要、下宇宙”的布局：

- 顶部显示当前智能体与快速切换。
- 底部是一块连续宇宙，所有智能体星系共享同一坐标空间。
- 每个星系中央直接显示该智能体的可编辑图标与强调色。
- 记忆显示为可交互星点；悬停时放大、发光并显示记忆标题。
- 宇宙支持触控板双指缩放和右下角加减按钮，范围 55%–240%。
- 第一分页不展示产品原则、开发备注或功能边界说明。

## 2026-10-31 · 二维记忆图谱

- 星海使用平面图谱，不使用椭圆轨道、球体或透视空间。
- 智能体是所在记忆图的恒星，图标位于中心。
- 每条记忆行星都用直线连接到自己的智能体恒星。
- 记忆之间支持独立关联；有 `memory_link` 时，以另一组虚线连接，交互模型接近 Obsidian 图谱。
- **2026-10-31 修正**：取消缩放回弹与过冲。双指缩放保持跟手，松手停在目标比例；按钮缩放使用无过冲的惯性减速曲线。
- 背景使用极淡的二维网格和星点，强调平面坐标感。

## 2026-10-31 · Emoji 图标与内容区对话

- 智能体图标改为从 Emoji 选择器中选择，不再使用 SF Symbols。
- 默认 Emoji：斐洛 `🐟`、克利俄 `✍️`、赫尔墨斯 `✨`。
- 旧数据中的 `fish.fill`、`pencil`、`sparkles` 等智能体符号会在启动迁移时转换成 Emoji。
- 智能体创建、外观编辑、侧栏头像、星海核心、状态页、聊天头像和悬浮聊天使用同一 Emoji 数据。
- 点击侧栏“最近”时不覆盖整个窗口：对话只替换侧栏右侧的内容区，侧栏始终保留。
- 整页对话中的“收起对话”只关闭内容区对话，并返回此前选中的分页。

### 对话进入位置

- 整页对话重新出现、从悬浮聊天展开或切换智能体时，默认显示最新消息，而不是滚动位置 0。
- 实现使用显式底部锚点，并在 `LazyVStack` 首帧布局后执行一次校准；延迟 60ms 的第二次定位用于覆盖消息较多时懒加载尚未完成的情况。
- 用户停留在当前对话内主动向上翻阅时，不强制拉回底部；只有在未读消息变化、发送状态变化或页面重新进入时跟随最新内容。

## 2026-10-31 · 整窗星海、玻璃侧栏与统一悬停

- 星海作为窗口最底层，铺满整个窗口，包括侧栏背后的空间。
- 页面标题、当前智能体摘要和其他内容浮在星海之上，侧栏不再切断宇宙画布。
- 侧栏改为 Liquid Glass：使用 SwiftUI `glassEffect`，macOS 26 以下回退到系统半透明材质。
- 侧栏保留圆角、浮层阴影和玻璃边缘高光，让后方星系与星点可以透出来。
- 所有按钮与标签页统一使用 `PhilotesInteractiveButtonStyle`。
- 悬停反馈统一为约 0.8% 放大、轻微提亮和柔和光晕；按下时轻微回缩。
- 减少动态效果开启时，悬停和按下反馈压缩为近乎即时。

## 2026-10-31 · 星海平移与深色玻璃

- Liquid Glass 侧栏在暗色模式下进一步降低底色不透明度，同时加深玻璃 tint，让背景星图更明显但不破坏文字对比度。
- 移除宇宙画布左上角固定的“宇宙”标签，避免与窗口红绿灯重叠。
- 星海支持鼠标拖拽平移，网格、星系核心、记忆星和连线作为一个整体移动。
- 拖拽松手时使用预测位移做短惯性减速，并限制最大位移，避免把整个图谱拖出可见区域。
- 底部百分比按钮同时承担“视图复位”：恢复 100% 缩放和零平移。

## 2026-10-31 · 视差星点与 Stage Manager 玻璃修复

- 星海增加独立的小星点视差层；拖动时只按世界平移的 22% 跟随移动，形成景深。
- 小星点层只做 18% 的缩放跟随，避免和主图谱完全粘连。
- 移除画布左上角残留的“宇宙”标签，操作提示仅保留在底部缩放控件旁。
- 侧栏 Liquid Glass 移除整块表面的 `.interactive()`，避免 Stage Manager 缩略图复用旧动态层。
- 在 App 激活/失活、窗口成为/失去 key window、窗口尺寸变化时，强制重建玻璃表面并刷新窗口阴影与绘制。

## 2026-10-31 · 侧栏与动效

- 采用类似 Codex 的严肃工作区侧栏，不使用传统的底部标签栏。
- 侧栏可在 238pt 与 72pt 之间折叠，折叠状态持久保存。
- 展开/收起使用弹簧动画；页面切换使用短淡入与轻微缩放。
- 星系、智能体卡片和悬浮聊天提供克制的悬停反馈。
- 动画必须尊重“减少动态效果”设置。

## 2026-10-31 · 自定义 API 与流式对话

- 第一套模型连接采用 OpenAI-compatible Chat Completions 协议，兼容用户自带的自定义 API。
- **已被“智能体级 API 选择”取代**：最初在全局设置页配置一份 API 地址、模型名和 API Key。
- API Key 只写入 macOS 钥匙串；SQLite、项目文档和 MemoryVault 均不保存凭据。
- 远程 API 必须使用 HTTPS；HTTP 仅允许 `localhost`、`127.0.0.1` 和 `::1`，便于连接本机模型服务。
- API 地址拒绝内嵌用户名或密码，账号凭据只能通过独立 Keychain 字段提供。
- 对话使用 SSE 流式接收，收到文本片段就实时显示；完整回复成功结束后才写入 SQLite。
- 用户消息在请求启动前写入 SQLite；配置无效或请求启动失败时，输入框保留原文，不生成占位回复。
- 每次生成都有独立 run ID。切换智能体、停止生成或开始新请求时，旧请求不能改写当前会话状态。
- 请求携带当前智能体的人设、非敏感记忆（最多 12 条）和最近 24 条对话。
- 连接测试使用非流式请求；错误信息会遮蔽 API Key。

## 2026-10-31 · 智能体级 API 选择

- API 连接不再是全局设置，而是每个智能体自己的配置。
- 创建智能体时直接选择 API，后续可从智能体卡片进入“智能体设定”修改。
- 可选类型包括“暂不配置”“DeepSeek”和“自定义兼容接口”。
- DeepSeek 预置 `https://api.deepseek.com/v1` 与 `deepseek-chat`，地址和模型仍可改成代理或 `deepseek-reasoner`。
- 自定义接口继续兼容 OpenAI Chat Completions，可填写基础地址或完整 `/chat/completions` 地址。
- 每个智能体分别保存 `apiProvider`、`apiBaseURL` 和 `apiModel`；API Key 以智能体 ID 对应的独立 Keychain account 保存。
- 旧版全局 API 地址和模型会自动迁移到第一个智能体，旧 Keychain 密钥也会迁入该智能体的 account。
- 清除密钥在保存设定时才生效，取消编辑不会提前删除钥匙串内容。

## 2026-10-31 · 模态窗口生命周期修复

- 不再监听所有 `NSWindow.didBecomeKey` / `didResignKey` 来做侧栏玻璃刷新。
- 打开 sheet 时，主窗口保持自身的玻璃状态，不跟随模态窗口 key 状态重建。
- 玻璃刷新只处理主窗口 resize 和 App 激活事件，并延迟到当前布局周期之后。
- 主窗口存在 attached sheet 时跳过玻璃强制绘制，避免布局递归和模态窗口失焦。
- 智能体设定与创建智能体窗口同时使用显式父级 binding 和 `dismiss()` 关闭。
- 已验证两个 sheet 可重复打开，取消与右上角关闭按钮均立即生效。

## 2026-10-31 · 三步智能体创建与人格档案

- 创建智能体改为三步向导，不再把所有字段塞进同一张表单。
- 第一步大字标题为“我是谁”：填写名字、选择 Emoji 图标和星系颜色。
- 第二步大字标题为“谁来帮助我思考”：选择或配置这个智能体自己的 API。
- 第三步大字标题为“我是怎么样的”：选择陪伴关系、性别、年龄感、性格气质和说话方式。
- 每个主要人格项都提供可点击选项和“自定义…”入口；选择自定义后展开自然语言输入框。
- 主动程度、情感表达和称呼放在默认折叠的“更多细节”中，另有全局人格补充描述。
- 人格内容保存为 `~/Library/Application Support/Philotes/Personas/agent-<id>.md`。
- Markdown 不包含 API Key，并会遮蔽明显的 token、password、secret 和 Bearer 字符串。
- 人格档案加入每次对话的系统提示词，确保第一次以及后续对话都能保持一致。
- 第一次成功收到该智能体的回复后，在聊天内容中央显示短暂的“人格已激活”悬浮提示。
- **2026-10-31 排布修正**：人格选项不再使用等宽自适应网格，改为按按钮内容宽度向前紧密流式堆积，仅在当前行放不下时换行。

## 2026-10-31 · 动作神态前缀与聊天侧栏

- **已被“可扩展情绪元数据”取代**：最初要求智能体以 `/(动作与神态)/` 开头。
- 本地读取时解析该前缀，动作与神态显示为正文上方的系统提示条。
- 气泡正文只显示标记之后的内容；标记本身仍按原始回复保存在 SQLite，便于重新解析。
- 流式回复在动作标记尚未闭合或正文尚未开始时显示等待状态，不会先闪出原始 `/()` 符号。
- 整页聊天右侧栏新增智能体档案卡，显示头像、名称、关系、模型、API 类型和人格 Markdown 中的人格字段与自定义描述。
- 解析同时兼容 `/（动作）/` 全角括号写法；不符合格式的旧消息保持原文显示。

## 2026-10-31 · 情绪值与侧栏曲线

- 回复前缀升级为可扩展结构：`/(情绪与神态;.情绪值)/`。
- 第一段写情绪、动作、表情或语气；第二段必须是一个 `-100` 到 `100` 的整数。
- `-100` 表示极度低落，`0` 表示平静，`100` 表示极度高涨；中间按低落、低缓、平静、轻快、高涨等区间解释。
- 以后新增字段继续使用 `;.` 分隔；解析器保留 metadata，不破坏前两段语义。
- 每条成功 assistant 回复提供一个情绪采样点；旧消息没有情绪值时不伪造数据。
- 整页聊天右侧栏显示最近 18 次采样组成的平滑情绪曲线、平均值与当前平均区间。
- 协议位于全局 system prompt，因此已有智能体下一轮回复会自动同步；无需重建旧智能体或人格文件。
- **2026-10-31 容错修正**：部分模型会输出 `/(情绪与神态;.情绪值)` 并漏掉结尾 `/`；本地解析在检测到 `;.` 和数值后允许裸 `)` / `）` 闭合，同时提示词仍要求完整 `)/`。

## 2026-10-31 · 聊天搜索与“忘记我”

- 聊天页右上角搜索按钮点击后向左展开输入栏，搜索范围限定为当前智能体的聊天记录和记忆。
- 搜索结果分为“聊天记录”和“记忆内容”两列；聊天结果点击后会滚到原始消息。
- 三点菜单提供“智能体设置”和红色“忘记我”。
- “忘记我”必须经过二次确认，并明确提示会删除聊天、记忆、人格文件和 API 密钥。
- 删除使用同一 SQLite 事务清理消息、记忆和关联边，再删除人格 Markdown 与 Keychain 中的智能体独立密钥。
- 删除当前智能体后自动切换到剩余智能体；若已无智能体则回到空状态并关闭聊天工作区。
- 三点菜单按钮使用独立 ZStack 遮罩底，避免 macOS `Menu` 默认样式吞掉按钮背景。

## 2026-10-31 · 星海顶部简化

- 星海顶部移除 `UNIVERSE` 眉题、智能体数量、长说明、当前智能体角色和重复摘要。
- 只保留“星海”、短句“所有记忆，一片宇宙。”以及紧凑的智能体切换胶囊。
- **已被液态玻璃悬浮栏取代**：顶部曾使用整块无边框模糊层和底部渐变。
- **2026-10-31 修正**：顶部改为独立圆角液态玻璃悬浮栏，不再使用整块模糊带。
- macOS 26+ 使用原生 `glassEffect`；旧系统回退到 `ultraThinMaterial` 加暗色 tint。
- 悬浮栏包含标题、短说明、搜索和智能体切换，使用轻微边缘高光与阴影与星系分层。

## 2026-10-31 · AGI Mac 操作能力

- 使用 OpenAI-compatible Chat Completions 的 `tools` 与流式 `tool_calls`，不解析自定义伪协议。
- **后续扩展已取代“第一版只有两个工具”**：基础工具仍是 `open_application` 和 `open_url`，高级工具另由默认关闭的开关控制。
- 模型只能提出动作；执行前必须在聊天里显示确认卡，并点击“允许一次”。
- **已被 2026-10-31 高级 Mac 控制决策取代**：原决定不开放 AppleScript、键盘鼠标模拟和屏幕读取；现在这些能力默认关闭，开启后仍须逐次确认。文件和凭据读取仍不开放。
- 应用解析优先使用 bundle ID，其次只在 `/Applications`、`/System/Applications` 和用户 Applications 中按名称查找。
- 网页只允许 HTTP/HTTPS。
- 一次最多提出 3 个动作；取消后全部不执行。
- 设置页提供全局“Mac 操作请求”开关，关闭后请求不携带 tools。
- **已被“工具结果回传模型”取代**：原实现只把结果写成一条本地 assistant 消息；现在结果还会作为标准 `tool` 消息回传同一模型，由其生成最终回复。

## 2026-10-31 · AppleScript、键鼠与屏幕快照

- `run_applescript` 使用 `NSAppleScript`，完整源码会原样显示在确认卡中，长度上限 20,000 字符。
- AppleScript 本身可以覆盖很广的系统操作，因此不把它误描述成“无害脚本”；安全边界是默认关闭、逐次展示、逐次允许，而不是黑名单式承诺拦截所有副作用。
- `click_screen` 使用 `CGEvent` 在全局屏幕坐标模拟左键或右键；`type_text` 支持 Unicode 文本分段输入；`press_key` 支持常用按键和 `cmd+shift+4` 一类组合键。
- **2026-10-31 权限注册修正**：键鼠首次使用调用 `AXIsProcessTrustedWithOptions(prompt: true)`，屏幕首次使用调用 `CGRequestScreenCaptureAccess()`；系统弹窗会把 Philotes 注册进对应设置列表。手动点击设置页按钮时也会先触发请求，再打开系统设置。
- macOS 26+ 使用 `com.apple.settings.PrivacySecurity.extension` 作为隐私设置深链，并分别传入 `Privacy_Accessibility`、`Privacy_ScreenCapture`；旧 `com.apple.preference.security` 保留为旧系统回退。
- `capture_screen` 使用 ScreenCaptureKit 获取一次主显示器快照，保存在 `~/Library/Application Support/Philotes/Screenshots/`。
- OCR 使用 Vision，识别简体中文和英文；最多把 8,000 个识别字符作为工具结果送入当前 API 上下文。截图文件本身不上传。
- 屏幕能力不代表后台录屏：每次读取都是用户明确允许的一次快照，模型只能请求下一次快照。
- **早期实现**：确认执行后构造 `assistant(tool_calls)` 与 `tool(tool_call_id)`，但 follow-up 不带 tools。
- **已被有界多批操作取代**：原 follow-up 完全不暴露工具，导致“打开网页后继续读屏”必须由用户再发一次消息；现在 follow-up 可以提出下一批动作，但不会自动执行。每批仍要单独确认，一轮最多 3 批、每批最多 3 个动作。
- 当前工具集与用户原文会一起写入 system prompt。用户请求查看当前页面、屏幕文字或总结所见内容时，智能体应主动调用 `capture_screen`；用户要求打开页面后继续读取时，应根据执行结果提出下一批截图，而不是声称看不到。
- 仅靠提示词仍可能出现“正文说想截图，但没有实际 tool call”。因此 App 会对屏幕、页面、网页、新闻、视频、图表、图片文字和 OCR 等视觉意图设置本地路由器：首轮没有先打开目标时直接强制 `capture_screen`；首轮先打开目标时，在执行结果后的下一轮强制截图。强制的是“提出工具请求”，本地确认仍不可省略。
- 设置页把该能力命名为“完整 Mac 操作能力”：开启后当前实现的全部 Mac 工具都会暴露给智能体，但“完整”不包含默认未实现的任意 shell 或后台持续录屏。
- follow-up 失败或达到批次上限时才回退为本地整理的操作结果消息。
- 首次 AppleScript 控制其他应用会触发系统“自动化”授权；`Info.plist` 提供 `NSAppleEventsUsageDescription` 说明。

## 2026-10-31 · 本地任务执行闭环

- 动作确认卡新增“执行整项任务”。打开应用/网页、切换窗口、读取 Safari 页面和截图可以自动连续推进；AppleScript、点击、键盘输入与快捷键仍逐批停下确认。
- App 维护当前 Mac 任务状态，因此“继续”“第一”“再来一次”等简短回复会沿用最近动作目标，而不是被当作没有工具意图的新闲聊。
- `MacIntentPlanner` 在本地决定首选工具：Safari 页面阅读优先 `read_safari_page`；只有真正需要画面时才使用 `capture_screen`。模型返回错工具、只写说明或空内容时，本地会纠正并生成真实工具卡。
- `read_safari_page` 读取 Safari 当前文档的标题、URL 和正文，即脚本字典里的 `text of front document`。它不依赖“允许来自 Apple 事件的 JavaScript”，因为 Safari 开发选项无法由 Philotes 自动请求。
- App 会记住本次任务的目标应用。每次截图或键鼠执行前重新激活 Safari、Notes 等目标，避免用户点击确认按钮后，Philotes 自己的窗口变成操作对象。
- 键鼠权限同时检查 Accessibility 信任和 `CGPreflightPostEventAccess()`；缺失时调用 `AXIsProcessTrustedWithOptions(prompt: true)` 与 `CGRequestPostEventAccess()`。
- 鼠标点击先发送 `mouseMoved`，等待 50ms 后再发送按下与抬起，兼容依赖悬停状态的窗口。
- 流式请求为空时自动重试一次非流式请求；tool choice 被 Provider 拒绝时依次降级为普通 tools、无 tools，避免兼容性问题表现为空回复。

## 2026-10-31 · 开发签名与钥匙串修复

- 问题：Debug 构建原先是纯临时签名，指定要求只有不断变化的 CDHash；重新构建后，旧 Keychain ACL 会把新版视为另一个应用并返回 `errSecAuthFailed`。
- 修复：本地构建通过 `app/PhilotesCodeSigning.requirements` 固定指定要求为 Bundle Identifier `com.shironotsu.philotes`，Clean 重建后仍满足同一个 Keychain ACL。
- 新 API Key 写入独立服务 `com.shironotsu.philotes.custom-api.v2`，避开旧临时签名留下的不可读 ACL。
- 读取时尝试迁移旧服务记录；遇到认证失败或交互不允许时，将其安全视为不存在，不阻塞用户重新输入密钥。
- Keychain 错误现在包含具体 `OSStatus`；`errSecAuthFailed` 会明确提示旧开发签名变化和重新输入。
- 已使用同签名应用的写入探针完成验证：写入后 Clean 重建，代码 CDHash 改变，新构建仍能成功读取并删除该记录。
